# Документ функциональных требований (FRD)
**Проект:** Корпоративный мессенджер «СТАНКИН»
**Тип приложения:** Клиент-серверное (React SPA + Spring Boot REST API + PostgreSQL)
**Версия:** 1.0

---

## 1. Введение и ролевая модель
Система предназначена для обеспечения изолированной образовательной коммуникации. В системе выделяются три основные роли с жестким разграничением прав (RBAC):
1. **Администратор (Admin):** Управляет пользователями, учебными группами и имеет доступ ко всем чатам.
2. **Преподаватель (Teacher):** Инициирует коммуникацию, создает чаты и управляет их настройками.
3. **Студент (Student):** Конечный пользователь, права которого ограничены рамками его учебной группы.

---

## 2. Модуль авторизации и управления профилями (FR-AUTH)

### 2.1 Авторизация
* **FR-AUTH-01 (Экран входа):** Стартовый экран системы с логотипом «СТАНКИН» должен предлагать пользователю выбор роли для входа посредством кнопок «Преподаватель» или «Студент».
* **FR-AUTH-02 (Идентификация студентов):** Для авторизации студента система должна использовать номер его студенческого билета в качестве логина.
* **FR-AUTH-03 (Идентификация сотрудников):** Авторизация преподавателей и администраторов должна осуществляться по уникальному текстовому логину.
* **FR-AUTH-04 (Безопасность сессии):** При успешной аутентификации сервер должен возвращать клиенту JWT-токен для последующих обращений к REST API.

### 2.2 Управление пользователями (Администрирование)
* **FR-AUTH-05 (Создание сотрудников):** Администратор системы должен иметь возможность создавать профили преподавателей и задавать им логины.
* **FR-AUTH-06 (Управление группами):** Администратор должен иметь возможность создавать сущности «Учебная группа» с обязательным указанием атрибута «Название/номер» (например, «ИДБ-24-18»).
* **FR-AUTH-07 (Привязка студентов):** Система должна позволять администратору привязывать профиль студента к конкретной учебной группе.

---

## 3. Модуль коммуникации и управления чатами (FR-CHAT)

### 3.1 Создание и настройка чатов
* **FR-CHAT-01 (Создание группового чата):** Преподаватель (и администратор) должен иметь право создавать «Групповой чат» с указанием его названия или «Номера/Индекса». Студенты лишены права создания чатов.
* **FR-CHAT-02 (Формирование состава участников):** Преподаватель должен добавлять одну или несколько учебных групп в созданный им групповой чат.
* **FR-CHAT-03 (Режим модерации / Read-Only):** Преподаватель должен иметь возможность перевести свой чат в закрытый режим. В этом режиме API-сервер должен блокировать попытки отправки сообщений от студентов (ошибка `403 Forbidden`), разрешая публикацию только преподавателю.

### 3.2 Навигация по чатам
* **FR-CHAT-04 (Боковая панель):** Левая часть интерфейса должна содержать панель «ЧАТЫ», отображающую список доступных пользователю диалогов (например, «Группа ИДБ-24-18», «Моя Loves group») с их аватарами.
* **FR-CHAT-05 (Поиск):** В верхней части списка чатов должно присутствовать текстовое поле «поиск...» со значком лупы для фильтрации списка.
* **FR-CHAT-06 (Быстрые действия):** На панели навигации (справа от заголовка «ЧАТЫ») должны быть размещены кнопки (иконки «+» и профиля) для создания нового диалога или группы.

---

## 4. Модуль обмена сообщениями (FR-MSG)

### 4.1 Типы сообщений
* **FR-MSG-01 (Текстовые сообщения):** Система должна поддерживать отправку, приём и хранение текстовых сообщений в рамках группового чата.
* **FR-MSG-02 (Файловые сообщения):** Система должна поддерживать передачу и хранение файловых сообщений (вложений). В панели ввода должна быть кнопка (скрепка) для прикрепления файлов.
* **FR-MSG-03 (Голосовые сообщения):** Интерфейс должен содержать кнопку-микрофон в правом нижнем углу для записи и отправки аудиосообщений.

### 4.2 Отображение сообщений в рабочей области
* **FR-MSG-04 (Идентификация отправителя):** Входящие сообщения в групповом чате должны отображаться слева, содержать аватар и текстовую подпись с именем/логином отправителя (например, "Студент 1", "Бубкин Виниамин").
* **FR-MSG-05 (Исходящие сообщения):** Сообщения текущего пользователя должны располагаться с правой стороны экрана, выделяться цветом (например, синим) и не требовать дублирования собственного имени.
* **FR-MSG-06 (Отправка):** Панель ввода сообщения должна содержать поле для ввода текста и кнопку со стрелкой («>») для инициации отправки. Если чат находится в режиме Read-Only (см. FR-CHAT-03), у студента данные элементы управления должны быть скрыты или заблокированы.

---

## 5. Модуль медиа-коммуникаций (FR-MEDIA)

* **FR-MEDIA-01 (Инициация видео-чата):** Преподаватель должен иметь возможность создать/запустить «Видео чат» в рамках выбранного группового чата.
* **FR-MEDIA-02 (UI медиа-вызовов):** В шапке (header) активного диалога, рядом с названием группы, должны отображаться функциональные кнопки:
  * Иконка видеокамеры для начала видео-трансляции/встречи.
  * Иконка телефонной трубки для инициации голосового вызова.
