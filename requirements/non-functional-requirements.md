# Документ нефункциональных требований (NFR)
**Проект:** Корпоративный мессенджер «СТАНКИН»  
**Архитектурный стек:** React SPA + Spring Boot REST API + PostgreSQL  
**Версия:** 1.0  

---

## 1. Производительность и пропускная способность (Performance Efficiency)

* **NFR-PERF-01 (Время отклика REST API):** Время обработки 95% входящих REST API запросов серверной частью на Spring Boot не должно превышать 200 мс при нормальной нагрузке.
* **NFR-PERF-02 (Задержка доставки сообщений):** Задержка передачи текстовых и голосовых сообщений между клиентами через протокол WebSockets / Server-Sent Events не должна превышать 500 мс.
* **NFR-PERF-03 (Задержка медиапотока):** Задержка передачи аудио- и видеосигнала в режиме «Видео чат» не должна превышать 300 мс (использование WebRTC / SFU).
* **NFR-PERF-04 (Оптимизация пагинации):** История текстовых и файловых сообщений в чате должна загружаться порциями (курсорная пагинация, по 30–50 сообщений) для предотвращения перегрузки React SPA приложения.

---

## 2. Безопасность и разграничение доступа (Security & Access Control)

* **NFR-SEC-01 (Аутентификация и сессии):** Аутентификация пользователей (по номеру студенческого билета или логину) должна быть защищена механизмом JWT (JSON Web Tokens) с ограниченным сроком жизни access-токена (не более 60 минут).
* **NFR-SEC-02 (Шифрование трафика):** Всё сетевое взаимодействие между React SPA клиентом и Spring Boot API должно осуществляться строго по защищенным протоколам HTTPS и WSS (TLS 1.3).
* **NFR-SEC-03 (Хранение паролей):** Пароли пользователей должны храниться в базе данных PostgreSQL в зашифрованном виде с использованием адаптивных хэш-функций (BCrypt с salt factor ≥ 10).
* **NFR-SEC-04 (Изоляция прав доступа RBAC):** Попытки прямого обращения студентов к защищенным эндпоинтам (например, создание чатов или отправка сообщений в закрытые чаты `isClosed == true`) должны блокироваться на уровне Spring Security с возвратом статуса `403 Forbidden`.
* **NFR-SEC-05 (Валидация файлов):** Загружаемые файловые сообщения должны проходить строгую валидацию MIME-типа, ограничение размера (до 50 МБ на файл) и проверки на исполняемый код.

---

## 3. Надежность и доступность (Reliability & Availability)

* **NFR-REL-01 (Коэффициент доступности):** Система должна обеспечивать коэффициент доступности (SLA) не менее 99.5% в период учебного процесса (с 08:00 до 22:00 по МСК).
* **NFR-REL-02 (Автоматическое переподключение):** При кратковременном разрыве сетевого соединения веб-клиент на React должен автоматически восстанавливать WebSocket-сессию без перезагрузки страницы.
* **NFR-REL-03 (Целостность данных):** База данных PostgreSQL должна обеспечивать свойство ACID для всех транзакций, а также ежедневное резервное копирование (дампы) с глубиной хранения 30 дней.

---

## 4. Совместимость и UX/UI (Compatibility & Usability)

* **NFR-COMP-01 (Кроссбраузерность):** Веб-приложение (React SPA) должно корректно функционировать и одинаково отображать интерфейс в актуальных версиях браузеров: Яндекс.Браузер, Google Chrome, Mozilla Firefox, Microsoft Edge, Safari.
* **NFR-COMP-02 (Адаптивность интерфейса):** Двухпанельный интерфейс (список чатов + рабочая область) должен адаптироваться под разрешения экранов от 1024x768 (планшеты/ноутбуки) до 1920x1080 и выше (Desktop).
* **NFR-USE-01 (Индикация состояний):** UI должен информировать пользователя об операциях отправки, блокировке ввода в закрытых чатах, а также ошибках авторизации понятными уведомлениями.

---

## 5. Масштабируемость и ограничения (Scalability & Constraints)

* **NFR-SCAL-01 (Одновременная нагрузка):** Система должна поддерживать одновременно не менее 1000 активных пользователей (онлайн-сессий) без ухудшения показателей времени отклика.
* **NFR-SCAL-02 (Индексация БД):** Для таблицы сообщений и связей чатов с группами в PostgreSQL должны быть созданы B-Tree и Hash индексы по внешним ключам и временным меткам для ускорения выборки.
